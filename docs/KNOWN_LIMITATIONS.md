# Known Limitations

- **Language Subset**: `cparse` supports only a subset of standard C as defined in `C_SUBSET.md`. Advanced features like bitfields, `goto`, `union`, or complex struct manipulation might be unsupported.
- **Preprocessor**: The lexer natively captures `#include` and `#define` as directives but drops them from the execution flow. Thus, `#define` macros are not expanded; their usages are parsed as regular identifiers. Interval analysis does substitute object-like integer defines (`#define N 5`); function-like macros and `#if`/`#ifdef` blocks are skipped (both branches of an `#if` are parsed).
- **Pointers & Aliasing**: The dataflow analysis (`dead-store` and `uninitialized-variable`) assumes variables are accessed directly. Inter-procedural analysis, pointer aliasing, or `&` address-taking impacts are largely ignored.
- **Inline Suppression**: Because the `cparse` lexer safely ignores comments, inline rule suppression relies on a lightweight Python regex parser that reads the original source text. It might be fooled by suppression patterns appearing within string literals.
- **Single File Analysis**: Cross-file dependency resolution is outside the scope of `sca`; each file is analyzed completely independently.
- **Type Information**: Type coercion rules, deep `sizeof` evaluation, and strict expression typing are minimally enforced.
- **Interval Analysis**: Only signed integer locals and parameters are tracked. Globals, `static` locals, variables whose address is taken, unsigned and floating-point values, array contents and function results are treated as unknown. A name declared twice in one function (e.g. two `i`s in different blocks) is not tracked, because scopes are matched by name. Values from different paths are merged, so a combination that can't actually happen together may still be reported (path-insensitivity). Only object-like `#define NAME <integer>` macros are understood. Analysis is per function; calls are not followed.
- **Input Contracts**: Parameters are searched one at a time with the others unknown, so a contract that depends on two parameters together (`a[lo + hi]`) is not found. Only signed integer parameters are covered. A contract is one range, or a range with one excluded value (`count != 0`). When interval imprecision makes a boundary uncertain, no contract is reported rather than a wrong one. Call sites are checked only within the same file, and only when the argument's range is known.
- **Misconception Diagnosis**: The mapping from rules to misconceptions is a fixed table (`sca/misconceptions.py`): it names the most common cause of a pattern, not necessarily the learner's actual reasoning. The web profile lives in the browser's `localStorage` and is not shared across devices.
